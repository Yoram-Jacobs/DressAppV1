# DressApp 完整技术用户手册

DressApp 个人衣橱生态系统、造型引擎、循环市场和管理面板的全面用户手册与技术参考指南。

---

## 1. 概述与技术栈

DressApp 是一款由 AI 驱动的个人衣橱管理器、造型顾问和循环交易市场。它帮助用户以数字化方式管理服装单品、自动裁剪和标记标签、接收结合天气和日历的穿搭建议、扫描欧盟数字产品护照（DPP）以及交易服装。

### 核心价值主张
- **数字衣橱录入**：拍摄快照或上传照片处理，具备自动背景移除、服装分类和属性标签生成功能。
- **AI 虚拟造型师**：一个对话式智能体，可结合上下文审阅您的衣橱、Google 日历事件和当地天气预报，从而推荐每日穿搭。
- **循环市场 (Circular Marketplace)**：安全的点对点（P2P）服装买卖、交换和租赁，以减少快时尚浪费。
- **单次穿着成本 (CPW) 分析**：深入洞察衣橱资产价值、利用率和使用优化情况。

### 技术架构
- **后端边缘层 (Backend Edge)**：Python 3.11 与 FastAPI，使用异步 Motor 驱动程序连接到 NVMe 存储上的专用本地部署 MongoDB 7.0 数据库。
- **前端 SPA**：React 19 单页应用程序，利用 `useSyncExternalStore` 自定义存储（`stylistStore`、`dailySuggestionsStore`、`useOutfitStore`、`useClosetStore`、`useSuitcaseStore`）、Tailwind CSS、Shadcn/UI 基础组件，以及支持 13 种语言环境的 `react-i18next`。
- **状态与网络优化**：进行中请求去重、15 分钟存储缓存以及 `visibilitychange` 标签页重新验证，在空闲时实现零后台 GET 请求。
- **本地机器学习与尺码预测**：基于 CPU 的本地 U2-Net（`rembg`）背景抠图、SegFormer-b2 服装解析、Fashion-CLIP 嵌入以及 ANSUR II 身体测量回归模型（`body_predictor.py`）。包含在 7860 端口上运行经过微调的 `Qwen 2.5 VL 3B` 模型（`Qwen2.5-VL-3B-Instruct-Q4_K_M.gguf` + `mmproj`）的专用本地部署 `dressapp-eyes` 容器，服务于免费层级（Free Tier）用户和自动配额回退。
- **对话式 STT/TTS**：实时客户端 Web Speech 语音识别回退、服务端多模态 Gemini 语音调制，以及设备端离线 Piper/Sherpa-ONNX 引擎。
- **外部集成服务**：用于获取天气的 OpenWeatherMap API、用于每日日程导出的 Google Calendar OAuth、OpenStreetMap（Nominatim）地址自动补全以及 PayPal Subscriptions/Checkout REST API。

## 2. 前提条件

### 宿主环境要求
- **硬件**：最低 8 GB RAM 的 VPS（例如托管生产环境 `dressapp.co` 的 Hetzner CPX32 VPS）。
- **依赖项**：Docker 与 Docker Compose 栈（包括本地部署 MongoDB 7.0、后端、eyes 推理服务器、前端和 Caddy TLS 终止）。
- **环境变量**：API 密钥配置（`GEMINI_API_KEY`、`EYES_API_TOKEN`、`DEEPGRAM_API_KEY`、`OPENWEATHER_API_KEY`、`PAYPAL_LIVE_CLIENT_ID/SECRET` 和 Google Calendar OAuth 令牌）。

### 用户应用要求
- **网页浏览器**：Google Chrome 或 Apple Safari（完整语音功能兼容性所需）。
- **权限**：授予相机权限（用于服装拍摄和二维码扫描）和麦克风权限（用于语音对话）。
- **零 BYOK 分层 AI**：免费用户使用 DressApp 的本地部署 Eyes（`Qwen 2.5 VL 3B`）模型；Manager 和 Professional 计划用户享有快速云端模型（`Gemini 3.5 Flash`）。无需用户提供任何 API 密钥。
- **网络**：用于 LLM 处理的有效网络连接，同时 IndexedDB 缓存可提供离线目录浏览。

## 3. 分步操作说明

### 3.1 录入服装（添加单品）
录入范式：照片拍摄、欧盟数字产品护照和电子商业收据。

#### A. 交互式相机与文件上传
1. 导航至 **添加单品 (Add Item)** 界面。
2. 选择 **拍照 (Take Photo)**（启动原生移动相机）或点击 **上传照片 (Upload Photos)**（打开操作系统文件选择器）。
3. 客户端在浏览器中计算图像的 SHA-256 和水平差分哈希（dHash）（约 100-180 毫秒），以与您现有的衣橱进行比对。
4. 如果发现匹配项，将打开 **重复预检对话框 (Duplicate Preflight Dialog)** 显示匹配的预览。选择 **跳过 (Skip)** 或 **仍然添加 (Add anyway)**。
5. 接受后，服务器启动 NDJSON 流。占位符预览框会在 5-7 秒内显示，允许您在后端完成打标的同时立即编辑单品详情。
6. 核对自动检测的标签（颜色、面料、版型、图案、场合）。如果抠图形状不正确，请更改 **类别 (Category)** 下拉菜单；这会触发 SegFormer 自动重新裁剪服装。
7. 点击 **保存 (Save)**，即可在后台 WebP 缩略图生成完成的同时，立即以乐观更新方式将单品绘制在衣橱网格中（约 16 毫秒）。

#### B. 扫描欧盟数字产品护照 (DPP)
1. 点击添加单品页面上的 **扫描二维码 (DPP)** 按钮。
2. 授予相机权限并对准印在服装零售标签上的二维码，或上传保存的二维码截图。
3. 后端解析 URL 并执行 SSRF 安全检查（阻止私有 IP 范围）。
4. 系统抓取 JSON-LD 模式以提取品牌、材料成分、供应链溯源、碳足迹和洗护指南。
5. 查看绿色 **已验证 DPP 数据 (Verified DPP Data)** 手风琴面板中显示的提取数据，然后点击 **保存 (Save)**。

#### C. 导入电子商业收据
1. 打开 **数字导入 (Digital Import)** 选项卡。
2. 选择子模式：**粘贴文本 (Paste Text)**、**上传图像 (Upload Image)**、**上传 PDF (Upload PDF)** 或输入 **网页链接 (Web Link)**。
3. 后端使用多模态视觉模型提取交易事实（品牌、价格、尺码、类别）。
4. 解析出的字段会被收据锁定，以保护它们免受未来视觉重新分析的覆盖。点击 **保存 (Save)** 确认。

### 3.2 对话式 AI 虚拟造型师
描述穿搭困扰，并接收免提口头穿搭建议。

1. 导航至 **AI 造型师 (AI Stylist)** 界面。
2. 点击聊天输入栏中的麦克风图标 `[Microphone]`。
3. 说出您的请求（例如：“雨天户外午餐，什么上衣适合搭配我的米色长裤？”）。
4. 如果支持 Web Speech，您的语音将在输入框中实时转录。如果不支持，应用会录制 WebM 文件并上传。
5. 后端将免费用户的查询路由至本地部署的 Eyes 容器（微调的 `Qwen 2.5 VL 3B`），并将 Manager 和 Professional 计划用户路由至快速云端模型（`Google Gemini 3.5 Flash`），遇到云端速率限制时自动回退至本地部署的 Eyes。
6. 造型师处理您的衣橱历史记录、当地天气预报和日历事件，以制定造型提议。
7. 造型师使用预选的语音配置文件（`puck`、`aoede` 或 `charon`）播报回复。
8. 点击卡片上的 **Play reply**（或在希伯来语模式下点击 **Replay**）以重新播放语音音频。

### 3.3 个人资料、偏好与子系统依赖关系
个人资料页面是 DressApp 的核心控制面板。配置字段直接影响下游模块的性能、路由和行为。

##### 手风琴板块依赖关系与原理

1. **照片与数字模特舞台 (`AvatarViewer2D` 与 `DynamicAvatar`)**
   - **为什么重要？**：使用双模式舞台（分割的真实人体照片抠图 vs 动态 2D 贝塞尔矢量 SVG 人体模特），在所有试衣画布上渲染您的视觉形象。
   - **子系统依赖关系**：照片抠图通过本地 U2-Net（`rembg`）进行背景抠图，并在浏览器中缩小至最大 1280px、82% 质量，以适应 MongoDB 的 16MB 文档上限。舞台应用校准的位置特征点（衣领到领口 `top-[14.5%]`、裤腰到腰线 `top-[36.5%]`、鞋履平面 `bottom-[2%]`）以及胸围/臀围成比例缩放（$scaleX$）。点击 *移除照片 (Remove Photo)* 可立即切换回 2D SVG 矢量人体模特。

2. **风格画像（保守度规则、着装规范）**
   - **为什么重要？**：为推荐的穿搭建立个人边界，防止 AI 生成不恰当的风格建议。
   - **子系统依赖关系**：所选参数（例如保守着装约束）直接输入至 Gemini 2.5 Flash 的造型提示词中，在展示前过滤匹配的衣橱输出。

3. **详情（姓名、电话、职业）**
   - **为什么重要？**：定制沟通语气并路由通知提醒。
   - **子系统依赖关系**：用户的姓名会动态解析到电子邮件和系统级推送中。电话号码作为计划提醒的后备注册信息。职业参数被输送至造型师 LLM 和 Trend Scout 个性化排序器以定制提议。

4. **身体测量与尺码（ANSUR II 回归模型与尺码预测器）**
   - **为什么重要？**：消除尺码猜测，实现自动零售尺码计算、外部零售尺码比对以及准确的虚拟叠穿。
   - **子系统依赖关系**：输入 4 项基本参数（**身高**、**体重**、**腰围**、**脚长**）会触发 scikit-learn ANSUR II 回归模型（`body_predictor.py`）自动预测 6 项结构尺寸（*肩宽*、*胸围*、*臀围*、*袖长*、*内缝裤长*、*外缝裤长*）。
     - **确定性尺码换算**：预测出连续测量值后，后端尺码引擎会将其动态转换为零售服装尺码：**衬衫尺码**（基于胸围的 XS-XXL）、**裤装尺码**（以英寸为单位的腰围）、**鞋码**（基于脚长和性别的美码男女款及欧码标准）、**连衣裙尺码**（基于胸围、腰围和臀围的 US 0-14+）以及 **文胸尺码**（基于胸围和估计下胸围的底围 + 罩杯）。
     - **自动填充**：这些推荐的零售尺码会自动填充到个人资料仪表盘内的 *详细编辑模式 (Detailed Edit Mode)* 字段中。
     - **集成**：测量数据由 **购物助手 (Shopping Assistant)** Chrome 扩展程序的内容脚本直接查询，以读取合作伙伴网站（Zara、Asos）上的尺码表并推荐尺码。

5. **生活方式（婚姻状况、性别）**
   - **为什么重要？**：量身定制默认推荐并为内容算法评分。
   - **子系统依赖关系**：性别选择直接影响每日 Trend Scout 卡片的排序逻辑。如果新闻卡片类别与用户的性别不匹配，算法会应用 -2.0 的评分惩罚，降低其在信息流中的排名。

6. **AI 模型路由与订阅计划（零 BYOK 分层路由与积分）**
   - **为什么重要？**：在无需任何用户 API 密钥的情况下，决定分层模型路由和积分消耗。
   - **子系统依赖关系**：免费层级用户路由至本地部署的 Eyes 容器（微调的 `Qwen 2.5 VL 3B`）。Manager 和 Professional 计划订阅者路由至快速云端模型（`Google Gemini 3.5 Flash`），并在触及配额限制时自动回退至本地部署的 Eyes。

7. **日程排程与推送（频率、每日闹钟、风格重点）**
   - **为什么重要？**：管理每日自动风格推送。
   - **子系统依赖关系**：激活 FastAPI 后端上的 `APScheduler` 定时任务。每天早晨，它会使用客户端的 VAPID 密钥通过 `pywebpush` 触发与所选风格重点参数相匹配的推送通知。

8. **Google 日历（OAuth 同步、导出规则）**
   - **为什么重要？**：将您的衣橱直接与现实世界中的日历事件连接起来。
   - **子系统依赖关系**：通过 Google OAuth 进行身份验证。排程器查询您的日历以识别事件、格式化穿搭方案，并将日历事件直接推送到您的 Google 日历日程中。

9. **位置服务（GPS 追踪、天气准确度）**
   - **为什么重要？**：协调适合天气的建议和本地交易半径筛选器。
   - **子系统依赖关系**：触发 `navigator.geolocation` 逆地理编码。坐标被发送至 OpenWeatherMap API 以调整造型师建议（例如暴雨天推荐防雨装）。它还用于计算本地市场商品列表和专家的距离（例如里斯本半径检查）。

10. **语音与语言（虚拟造型师语音选择）**
    - **为什么重要？**：确立文本词典语言环境和语音调制。
    - **子系统依赖关系**：通过 `react-i18next` 控制用于翻译的活动语言。语音选择将 BCP-47 语音代码（例如 `he-IL` 或 `ar-JO`）映射到客户端 Web Speech 合成语音或离线 Piper TTS 模型。

11. **邀请好友（分享载荷 API）**
    - **为什么重要？**：为免费衣橱扩容提供裂变循环。
    - **子系统依赖关系**：将推荐人的 MongoDB ID 附加到 URL。新注册会动态查询此 ID，并原子化地将推荐人的 `closet_capacity_bonus` 增加 +10 个槽位，从而修改 `closet.py` 中的上限守卫。

### 3.4 衣橱洞察仪表盘 (Wardrobe Insights)
分析衣橱资产价值、追踪服装利用率以及单次穿着成本（CPW）参数。

1. 导航至 **衣橱洞察 (Wardrobe Insights)**。
2. **审阅指标**：
   - *衣橱总值 (Closet Worth)*：购买价格的动态总和。
   - *衣橱利用率 (Closet Utilization)*：衣橱中至少穿过一次的服装百分比。
   - *平均单次穿着成本 (CPW)*：按 `价格 / 穿着次数` 计算。
3. **分布图表**：切换选项卡以查看 Recharts 可视化图表：
   - *调色板*：映射的十六进制颜色代码分布。
   - *材质*：面料百分比分布。
   - *子类别*：映射的子类别分布。
4. **效率排行榜**：查看单次穿着成本（CPW）得分最低的前 5 件服装。

### 3.5 穿搭画布与规划器 (Outfit Canvas)
在交互式 2D 虚拟形象画布上构建、叠穿和审阅穿搭提议。

1. 打开 **穿搭画布 (Outfit Canvas)** 规划器。
2. **外套叠穿（双画布）**：如果您的穿搭在上衣外包含外套（例如夹克），页面将渲染两个垂直画布模块：“含外套 (With Outerwear)”（显示叠穿的夹克）和“不含外套 (Without Outerwear)”（显示里面的上衣）。
3. **交互式 2D 元素**：直接点击虚拟形象身上的任何服装单品，应用会带您直接跳转到该服装的详情界面。
4. **审阅指标选项卡**：点击详情按钮并选择 **指标 (Metrics)** 选项卡，查看兼容性标准的进度条：
   - *色彩和谐度 (Color Harmony)*（中性色协调）
   - *图案兼容性 (Pattern Compatibility)*（防止图案冲突）
   - *合身度 (Body Fitting)*（尺码匹配）
   - *天气匹配度 (Weather Match)*（季节适宜性）
   - *场合匹配度 (Event Match)*（活动得体度）
   - *地点匹配度 (Location Match)*（保守着装规则检查）
5. **重命名/描述**：点击铅笔图标编辑穿搭名称和描述。

### 3.6 行李箱助手 (Suitcase Assistant)
整理您的旅行打包需求，避免过度打包。

1. 前往 **行李箱 (Suitcase)** 页面并填写旅行背景表单（目的地、开始/结束日期、旅行类别、日历事件）。
2. AI 会根据旅行时长和天气预报生成定制化的打包清单和每日穿搭。
3. 检查打包进度。如果缺少重要物品（例如雨天用的雨伞、海滩用的泳衣），系统会提醒您并推荐来自交易市场或本地商店的匹配商品。
4. 使用集成的聊天框微调建议（例如“将第 2 天改为休闲晚装”）。助手会在保留其余列表的同时编辑行李箱内容。
5. 点击 **批准行李箱 (Approve Suitcase)** 以最终确定您的计划。

### 3.7 日程排程与推送提醒
设置每日造型提醒，以自动接收穿搭推荐。

1. 打开 **个人资料 (Profile)** 并前往 **日程排程与推送 (Scheduler & Push)**。
2. 开启通知开关，设置每日通知时间、工作日频率和造型重点主题。
3. 每天早晨，后台定时任务（`APScheduler`）会检查天气预报并发送推送通知。
4. 点击设备上的通知（或查看网页应用的通知中心）以打开显示 3 套造型建议的提议对话框。
5. 将建议直接保存到您的 **衣橱日记 (Wardrobe Diary)** 中。

### 3.8 交易市场（转售、租赁、交换、捐赠）
参与点对点（P2P）循环时尚交易市场。

- **创建商品列表**：打开单品的详情页面，选择 **编辑意图 (Edit Intent)**，并选择一个非私有意图：
  - *出售 (For Sale)*：输入标价和货币（通过区域语言环境偏好检测您的默认货币）。
  - *出租 (Rent)*：设置每日租金标准和借用条件。
  - *交换 (Swap)*：将单品标记为开放交换。
  - *捐赠 (Donate)*：免费发布单品。
- **状态同步**：商品列表会自动传播到信息流中。客户端使用 `useSyncExternalStore` 和 IndexedDB 缓存以零延迟加载搜索参数。
- **试穿沙盒**：租客/买家可以在结账前将市场商品与自己私人衣橱中的单品进行搭配试穿测试。
- **交易结账**：
  - *购买/租赁*：通过集成的 PayPal 按钮完成交易。捕获的 Webhook 会通知卖家，将列表状态翻转为已售/已租，并在扣除 7% 的平台费用后将交易记录在账本中。
  - *易货（交换）*：潜在交换者提出交易申请。发布者会收到确认电子邮件以选择接受或拒绝。

### 3.9 管理后台仪表盘 (Admin Panel)
系统存活状态验证、财务记账和用户账户管理。

1. 导航至 `/admin`（仅对管理员角色开放）。

## 5. 常见问题排查

### HTTP 402 Payment Required（需要付款）
- **问题**：录入被阻止。您已达到 50 件衣橱单品的基础上限（或算上推荐奖励最高 150 件单品）。
- **解决方案**：前往 **定价页面**（`/pricing`）并订阅 Manager 或 Professional 计划，或分享您的邀请链接，每有一人注册即可获得 +10 个槽位（最高 150 件单品）。

### DPP 上的 SSRF 阻止 / DNS 错误
- **问题**：扫描的二维码护照 URL 解析失败。
- **解决方案**：解析器会阻止私有 IP 地址（例如 `127.0.0.1`、`192.168.x.x`）以保护内部服务器。请确保二维码指向公共域名。

### 相机 / 麦克风权限被拒绝
- **问题**：拍摄/扫描视口显示“X”错误屏幕，或语音输入失败。
- **解决方案**：打开浏览器权限，为该域名启用相机和麦克风访问权限，然后重新加载。

### 造型师聊天失败 / 速率限制
- **问题**：聊天显示错误或卡死。
- **解决方案**：服务器会捕获 Gemini `429` 速率限制并回退至基于规则的衣橱选择算法。请验证您的互联网连接。

### VPS 内存不足 (OOM) 峰值
- **问题**：上传过程中 CPU/RAM 达到峰值。
- **解决方案**：录入对超过 5 件单品的批次使用顺序队列锁。请确保服务器至少具有 4 GB RAM。

## 6. 使用限制

- **浏览器 Web Speech API**：原生语音转文本翻译仅限于 Chrome 和 Safari；其他浏览器会回退至标准文本输入。
- **离线客户端调制**：移动端离线 Piper ONNX 语音合成使用的语音配置文件少于服务端 Gemini 音频模态。
- **图像大小约束**：虚拟形象和个人资料上传内容会在浏览器本地压缩至 82% 质量，以适应 16MB 的 MongoDB 文档边界。
- **收据解析范围**：高度模糊、扭曲或手写的收据可能会提取数据失败。
