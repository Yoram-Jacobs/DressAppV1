# DressApp 完全技術ユーザーマニュアル

DressApp のパーソナルワードローブエコシステム、スタイリングエンジン、循環型マーケットプレイス、および管理パネルに関する包括的なユーザーマニュアルおよび技術リファレンスガイドです。

---

## 1. 概要とテクノロジースタック

DressApp は、AIを活用したパーソナルワードローブ管理ツール、スタイリングアドバイザー、および循環型マーケットプレイスです。衣類のデジタル管理、自動切り抜き・タグ付け、天気やカレンダーの予定に合わせたコーディネートの提案、EUデジタル製品パスポート（DPP）のスキャン、および衣類の取引をサポートします。

### 主な価値提供
- **デジタルワードローブ登録**: 背景の自動削除、衣類カテゴリの分類、属性タグの生成を含む、撮影またはアップロードした写真の処理。
- **AIバーチャルスタイリスト**: ワードローブ、Google カレンダーの予定、および現地の天気予報を文脈に合わせて分析し、毎日のコーディネートを提案する対話型エージェント。
- **循環型マーケットプレイス**: ファストファッションの廃棄を削減するための、安全な個人間（P2P）での衣類の売買、交換、およびレンタル。
- **着用1回あたりのコスト (CPW) 分析**: ワードローブの資産価値、稼働率、および利用最適化に関するインサイト。

### 技術アーキテクチャ
- **バックエンドエッジ**: Python 3.11 と FastAPI を使用し、非同期 Motor ドライバーを介して NVMe ストレージ上の専用オンプレミス MongoDB 7.0 データベースに接続しています。
- **フロントエンド SPA**: React 19 シングルページアプリケーション。`useSyncExternalStore` カスタムストア（`stylistStore`、`dailySuggestionsStore`、`useOutfitStore`、`useClosetStore`、`useSuitcaseStore`）、Tailwind CSS、Shadcn/UI プリミティブ、および13ロケールに対応する `react-i18next` を活用しています。
- **状態とネットワークの最適化**: 処理中リクエストの重複排除、15分間のストアキャッシュ、および `visibilitychange` によるタブ再検証により、アイドル時のバックグラウンド GET リクエストをゼロに抑えています。
- **ローカル機械学習＆サイズ算出**: CPUローカルの U2-Net（`rembg`）背景マッティング、SegFormer-b2 衣類解析、Fashion-CLIP 埋め込み、および ANSUR II 身体測定回帰モデル（`body_predictor.py`）。無料プラン（Free Tier）ユーザーおよび自動クォータフォールバック用に、ポート 7860 でファインチューニング済み `Qwen 2.5 VL 3B` モデル（`Qwen2.5-VL-3B-Instruct-Q4_K_M.gguf` + `mmproj`）を実行する専用のオンプレミス `dressapp-eyes` コンテナを含みます。
- **対話型 STT/TTS**: クライアント側のリアルタイム Web Speech 音声認識フォールバック、サーバー側のマルチモーダル Gemini 音声変調、およびデバイス上のオフライン Piper/Sherpa-ONNX エンジン。
- **外部連携サービス**: 気象取得用の OpenWeatherMap API、毎日のスケジュール出力用の Google Calendar OAuth、OpenStreetMap（Nominatim）住所自動補完、および PayPal Subscriptions/Checkout REST API。

## 2. 前提条件

### ホスト環境要件
- **ハードウェア**: 最低 8 GB RAM の VPS（例：本番環境 `dressapp.co` をホストする Hetzner CPX32 VPS）。
- **依存関係**: Docker ＆ Docker Compose スタック（オンプレミス MongoDB 7.0、バックエンド、eyes 推論サーバー、フロントエンド、および Caddy TLS 終端を含む）。
- **環境変数**: APIキー設定（`GEMINI_API_KEY`、`EYES_API_TOKEN`、`DEEPGRAM_API_KEY`、`OPENWEATHER_API_KEY`、`PAYPAL_LIVE_CLIENT_ID/SECRET`、および Google Calendar OAuth トークン）。

### ユーザーアプリ要件
- **Webブラウザ**: Google Chrome または Apple Safari（音声機能の完全な互換性のために必要）。
- **権限**: カメラ権限（衣類の撮影やQRスキャン用）およびマイク権限（音声会話用）の許可。
- **ゼロBYOK階層型AI**: 無料プランのユーザーは DressApp のオンプレミス Eyes（`Qwen 2.5 VL 3B`）モデルを使用し、Manager および Professional プランのユーザーは高速クラウドモデル（`Gemini 3.5 Flash`）を利用します。ユーザーがAPIキーを用意する必要はありません。
- **ネットワーク**: LLM処理のためのアクティブな接続（IndexedDB キャッシュによりオフラインでのカタログ閲覧が可能）。

## 3. ステップバイステップの手順

### 3.1 衣類の登録（アイテムの追加）
登録方法：写真撮影、EUデジタル製品パスポート、および電子商取引レシート。

#### A. インタラクティブカメラ、混在バッチアップロード＆自動3パイプラインルーティング
1. **アイテムを追加 (Add Item)** 画面に移動します。
2. **写真を撮る (Take Photo)**（ネイティブカメラを起動）を選択するか、**写真をアップロード (Upload Photos)**（OSのファイル選択を開く）をクリックします。手動のモードタブを選択することなく、1回のバッチで異なる特徴を持つ複数の写真（単品アイテム、モデル／マネキンの全身コーデ、未着用の服の山／置き画クラスター）を自由に混在してアップロードできます。
3. クライアントはブラウザ内で各画像の SHA-256 と水平差分ハッシュ（dHash）を計算（約100〜180ms）し、既存のクローゼットと重複照合します。
4. 一致するものが見つかった場合、一致するプレビューを表示する **重複事前確認ダイアログ (Duplicate Preflight Dialog)** が開きます。**スキップ (Skip)** または **そのまま追加 (Add anyway)** を選択します。
5. **自動3パイプライン写真ルーティング (`detect_photo_pipeline`)**: 承認された各写真について、`clothing_parser.py` が SegFormer セマンティックマスク（`face_skin_ratio`、`anatomical_stack`、連結成分）を解析し、最適なパイプラインへ自動的に振り分けます：
   - **`single` パイプライン**: スタジオ品質のアルファマッティング（`rembg` + SegFormer マスク交差）で単一の衣類を切り抜きます。
   - **`multi` パイプライン**: モデルやマネキンが着用した全身コーデから、トップス・ボトムス・アウター・靴・アクセサリーの個別切り抜きを抽出します。
   - **`mass` パイプライン**: 未着用の服の集合、置き画（フラットレイ）、または壁フックに掛けられた複数の衣類（`parse_unworn_cluster`）を処理し、プリント柄を保護しながら個別のアイテムに分離します。
6. サーバーは数秒以内にプログレッシブ NDJSON フレーム（`detect`、`field`、`item`、`done`）をストリーミング配信し、バックエンドがタグ付けを完了する間に即座に詳細を編集できます（全13言語での **スウェット＆パーカー (`Sweatshirts & Hoodies`)** と **Tシャツ (`T-Shirt`)** の正確な識別、および60種類以上の **伝統・文化衣装** の分類を含む）。
7. 自動検出されたタグ（色、素材、フィット感、柄、ドレスコード、着用シーン）を確認します。切り抜き形状が正しくない場合は、**カテゴリ (Category)** ドロップダウンを変更すると、SegFormer が自動的に衣類を再切り抜きします。
8. **保存 (Save)** をクリックすると、バックグラウンドでの WebP サムネイル生成および Nano Banana 生成補完が完了するまでの間、クローゼットグリッドにアイテムが即座（約16ms）に反映されます。

#### B. EUデジタル製品パスポート (DPP) のスキャン
1. アイテム追加ページで **QRをスキャン (DPP)** ボタンをタップします。
2. カメラ権限を許可し、衣類の小売ラベルに印刷されたQRコードに合わせるか、保存したQRスクリーンショットをアップロードします。
3. バックエンドはURLを解決し、SSRF安全チェック（プライベートIP範囲のブロック）を実行します。
4. システムは JSON-LD スキーマをスクレイピングして、ブランド、素材構成、サプライチェーン追跡、カーボンフットプリント、およびケアガイドラインを抽出します。
5. 緑色の **確認済みDPPデータ (Verified DPP Data)** アコーディオンパネルに表示された抽出データを確認し、**保存 (Save)** をクリックします。

#### C. 電子レシートのインポート
1. **デジタルインポート (Digital Import)** タブを開きます。
2. サブモードを選択します：**テキスト貼り付け (Paste Text)**、**画像アップロード (Upload Image)**、**PDFアップロード (Upload PDF)**、または **Webリンク (Web Link)** の入力。
3. バックエンドはマルチモーダルビジョンモデルを使用して、取引情報（ブランド、価格、サイズ、カテゴリ）を抽出します。
4. 解析されたフィールドはレシートロックされ、将来の視覚的再分析による上書きから保護されます。**保存 (Save)** をクリックして確定します。

### 3.2 対話型AIバーチャルスタイリスト
スタイリングの悩みを相談し、ハンズフリーの音声でコーディネートのアドバイスを受け取ります。

1. **AIスタイリスト (AI Stylist)** 画面に移動します。
2. チャット入力バーのマイクアイコン `[Microphone]` をクリックします。
3. リクエストを話します（例：「雨の日の屋外ランチで、ベージュのパンツに合うトップスは？」）。
4. Web Speech がサポートされている場合、音声は入力ボックスにリアルタイムで文字起こしされます。サポートされていない場合、アプリは WebM ファイルを録音してアップロードします。
5. バックエンドは、無料プランのユーザーのクエリをオンプレミスの Eyes コンテナ（ファインチューニング済み `Qwen 2.5 VL 3B`）にルーティングし、Manager および Professional プランのユーザーを高速クラウドモデル（`Google Gemini 3.5 Flash`）にルーティングします（クラウドのレート制限時にはオンプレミス Eyes へ自動フォールバックします）。
6. スタイリストはワードローブの履歴、現地の天気予報、およびカレンダーの予定を処理してスタイリング提案を作成します。
7. スタイリストは事前選択された音声プロファイル（`puck`、`aoede`、または `charon`）を使用して応答を読み上げます。
8. カード上の **Play reply**（ヘブライ語モードでは **Replay**）をタップすると、音声オーディオを再生できます。

### 3.3 プロフィール、環境設定、およびサブシステムの依存関係
プロフィールページは DressApp のコアコントロールパネルとして機能します。設定フィールドは、下流モジュールのパフォーマンス、ルーティング、および動作に直接影響を与えます。

##### アコーディオンセクションの依存関係と根拠

1. **写真＆デジタルアバターステージ (`AvatarViewer2D` ＆ `DynamicAvatar`)**
   - **なぜ重要か？**: デュアルモードステージ（セグメント化された実写全身写真の切り抜き vs 動的2DベジェベクトルSVGマネキン）を使用して、すべての試着キャンバスにわたって視覚的なアイデンティティをレンダリングします。
   - **サブシステムの依存関係**: 写真の切り抜きはローカルの U2-Net（`rembg`）を介して背景マッティングされ、MongoDB の 16MB ドキュメント上限に収まるようブラウザ内で最大 1280px・品質 82% に縮小されます。ステージは校正された位置ランドマーク（襟から首元 `top-[14.5%]`、ウエストバンドからウエストライン `top-[36.5%]`、靴の平面 `bottom-[2%]`）および胸囲／ヒップの比例スケーリング（$scaleX$）を適用します。*写真を削除 (Remove Photo)* をクリックすると、即座に 2D SVG ベクトルマネキンに切り替わります。

2. **スタイルプロファイル（露出度ルール、ドレスコード）**
   - **なぜ重要か？**: 推奨されるコーディネートの個人的な境界線を確立し、AIが不適切なスタイル提案を生成するのを防ぎます。
   - **サブシステムの依存関係**: 選択されたパラメータ（控えめな服装の制約など）は Gemini 2.5 Flash のスタイリングプロンプトに直接供給され、表示される前に一致するワードローブ出力をフィルタリングします。

3. **詳細情報（氏名、電話番号、職業）**
   - **なぜ重要か？**: コミュニケーションのトーンをカスタマイズし、通知アラートをルーティングします。
   - **サブシステムの依存関係**: ユーザーの氏名はメールやシステムレベルのプッシュ通知に動的に挿入されます。電話番号はスケジュールされたアラートのフォールバック登録として機能します。職業パラメータはスタイリストLLMおよび Trend Scout のパーソナライズランカーに供給され、提案をカスタマイズします。

4. **身体測定＆サイズ設定（ANSUR II 回帰モデル＆サイズ予測器）**
   - **なぜ重要か？**: サイズ選びの推測を排除し、小売サイズの自動計算、外部ECサイトのサイズ比較、および正確なバーチャル重ね着を可能にします。
   - **サブシステムの依存関係**: 4つの基本パラメータ（**身長**、**体重**、**ウエスト**、**足の長さ**）を入力すると、scikit-learn ANSUR II 回帰モデル（`body_predictor.py`）がトリガーされ、6つの構造的寸法（*肩幅*、*胸囲*、*ヒップ*、*袖丈*、*股下*、*総丈*）を自動予測します。
     - **決定論的サイズ換算**: 連続的な測定値が予測されると、バックエンドのサイズエンジンがそれらを小売の衣類サイズに動的に変換します：**シャツサイズ**（胸囲に基づく XS〜XXL）、**パンツサイズ**（インチ単位のウエスト）、**靴のサイズ**（足の長さおよび性別に基づく米国メンズ／ウィメンズおよびEU基準）、**ドレスサイズ**（胸囲、ウエスト、ヒップに基づく US 0〜14+）、および **ブラサイズ**（胸囲と推定アンダーバストに基づくバンド＋カップ）。
     - **自動入力**: これらの推奨小売サイズは、プロフィールダッシュボード内の *詳細編集モード (Detailed Edit Mode)* フィールドに自動的に入力されます。
     - **連携**: 測定値は **ショッピングアシスタント** Chrome 拡張機能のコンテンツスクリプトから直接照会され、提携Webサイト（Zara、Asosなど）のサイズ表を読み取ってサイズを推奨します。

5. **ライフスタイル（配偶者の有無、性別）**
   - **なぜ重要か？**: デフォルトの推奨を調整し、コンテンツアルゴリズムのスコアを計算します。
   - **サブシステムの依存関係**: 性別の選択は、毎日の Trend Scout カードのランキングロジックに直接影響します。ニュースカードのカテゴリがユーザーの性別と一致しない場合、アルゴリズムは -2.0 のスコアペナルティを適用し、フィード内の順位を下げます。

6. **AIモデルルーティング＆サブスクリプションプラン（ゼロBYOK階層型ルーティング＆クレジット）**
   - **なぜ重要か？**: ユーザーのAPIキーを一切必要とせずに、階層型のモデルルーティングとクレジット消費を決定します。
   - **サブシステムの依存関係**: 無料プランのユーザーはオンプレミスの Eyes コンテナ（ファインチューニング済み `Qwen 2.5 VL 3B`）にルーティングされます。Manager および Professional プランの契約者は高速クラウドモデル（`Google Gemini 3.5 Flash`）にルーティングされ、クラウドの利用枠制限時にはオンプレミス Eyes へ自動的にフォールバックします。

7. **スケジューラー＆プッシュ通知（頻度、毎日のアラーム、スタイルフォーカス）**
   - **なぜ重要か？**: 毎日の自動スタイルプッシュ通知を管理します。
   - **サブシステムの依存関係**: FastAPI バックエンド上の `APScheduler` cron ジョブをアクティブ化します。毎朝、選択されたスタイルフォーカスパラメータに一致するプッシュ通知を、クライアントの VAPID キーを使用して `pywebpush` 経由でトリガーします。

8. **Google カレンダー（OAuth 同期、エクスポートルール）**
   - **なぜ重要か？**: ワードローブを現実世界のカレンダーイベントと直接結びつけます。
   - **サブシステムの依存関係**: Google OAuth を介して認証します。スケジューラーはカレンダーを照会して予定を特定し、コーディネートをフォーマットして、Google カレンダーの予定表に直接プッシュします。

9. **位置情報サービス（GPS追跡、天気精度）**
   - **なぜ重要か？**: 天候に適した提案と地域の取引半径フィルターを調整します。
   - **サブシステムの依存関係**: `navigator.geolocation` の逆ジオコーディングをトリガーします。座標は OpenWeatherMap API に送信され、スタイリストの推奨（土砂降りの際のレインウェアなど）を調整します。また、地域のマーケットプレイス出品やエキスパートの距離計算（リスボン半径チェックなど）も行います。

10. **音声と言語（バーチャルスタイリストの音声選択）**
    - **なぜ重要か？**: テキスト辞書のロケールと音声の抑揚を確立します。
    - **サブシステムの依存関係**: `react-i18next` を介して翻訳のアクティブな言語を制御します。音声選択は BCP-47 音声コード（`he-IL` や `ar-JO` など）をクライアントの Web Speech 合成音声またはオフラインの Piper TTS モデルにマッピングします。

11. **友達を招待（共有ペイロードAPI）**
    - **なぜ重要か？**: 無料でクローゼットを拡張するためのバイラルループを提供します。
    - **サブシステムの依存関係**: 紹介者の MongoDB ID を URL に付加します。新規登録時にこの ID が動的に照会され、紹介者の `closet_capacity_bonus` がアトミックに +10 スロット増加し、`closet.py` の上限ガードが更新されます。

### 3.4 ワードローブインサイトダッシュボード
ワードローブの資産価値の分析、衣類稼働率の追跡、および着用1回あたりのコスト（CPW）パラメータを確認します。

1. **Wardrobe Insights（ワードローブインサイト）** に移動します。
2. **メトリクスの確認**:
   - *クローゼット資産価値 (Closet Worth)*: 購入価格の動的合計。
   - *クローゼット稼働率 (Closet Utilization)*: 少なくとも1回着用されたクローゼット衣類の割合。
   - *平均着用コスト (Average Cost-per-Wear / CPW)*: `価格 / 着用回数` として計算されます。
3. **分布グラフ**: タブを切り替えて Recharts による視覚化を表示します：
   - *カラーパレット*: マッピングされた16進数カラーコードの分布。
   - *素材*: 素材の割合の分布。
   - *サブカテゴリ*: マッピングされたサブカテゴリ。
4. **効率リーダーボード**: 着用1回あたりのコスト（CPW）スコアが最も低い上位5着の衣類を表示します。

### 3.5 コーディネートキャンバス＆プランナー
インタラクティブな 2D アバターキャンバス上でコーディネート提案を構築、重ね着、および確認します。

1. **Outfit Canvas（コーディネートキャンバス）** プランナーを開きます。
2. **アウターの重ね着（デュアルキャンバス）**: コーディネートにトップスの上に着るアウター（ジャケットなど）が含まれている場合、ページには「アウターあり (With Outerwear)」（ジャケットを重ねた状態）と「アウターなし (Without Outerwear)」（下のトップスが見える状態）の2つの垂直キャンバスモジュールがレンダリングされます。
3. **インタラクティブな2D要素**: アバターの身体上の任意の衣類を直接タップすると、その衣類の詳細画面に直接移動します。
4. **メトリクスタブの確認**: 詳細ボタンをクリックし、**Metrics（メトリクス）** タブを選択して互換性基準のプログレスバーを表示します：
   - *カラーハーモニー (Color Harmony)*（色の調和）
   - *パターンの互換性 (Pattern Compatibility)*（柄の衝突防止）
   - *ボディフィッティング (Body Fitting)*（サイズの一致）
   - *天候マッチ (Weather Match)*（季節の適合性）
   - *イベントマッチ (Event Match)*（アクティビティの適切性）
   - *ロケーションマッチ (Location Match)*（露出度ルールのチェック）
5. **名前変更／説明**: 鉛筆アイコンをクリックしてコーディネートの名前と説明を編集します。

---

### 3.6 スーツケースアシスタント
荷物を詰めすぎることなく、旅行のパッキング要件を整理します。

1. **Suitcase（スーツケース）** ページに移動し、旅行コンテキストフォーム（目的地、開始／終了日、旅行カテゴリ、カレンダーの予定）に入力します。
2. AIが旅行期間と天気予報に基づいて、カスタマイズされたパッキングリストと毎日のコーディネートを生成します。
3. パッキングの進捗状況を確認します。重要なアイテム（雨の日の傘、ビーチ用の水着など）が不足している場合、システムがアラートを出し、マーケットプレイスや地域の店舗から一致するアイテムを提案します。
4. 統合されたチャットボックスを使用して提案を微調整します（例：「2日目をカジュアルな夜着に変更して」）。アシスタントはリストの残りの部分を維持したままスーツケースを編集します。
5. **Approve Suitcase（スーツケースを承認）** をタップしてプランを確定します。

---

### 3.7 スケジューラー＆プッシュリマインダー
毎日のスタイリングアラートを設定して、コーディネートの推奨を自動的に受け取ります。

1. **プロフィール** を開き、**Scheduler & Push（スケジューラー＆プッシュ）** に移動します。
2. 通知をオンにし、毎日の通知時刻、曜日の頻度、およびスタイリングフォーカステーマを設定します。
3. 毎朝、バックグラウンドの cron タスク（`APScheduler`）が天気予報を確認し、プッシュ通知を送信します。
4. デバイス上の通知をタップする（またはWebアプリの通知センターを表示する）と、3つのスタイリング提案を表示する提案ダイアログが開きます。
5. 提案を **Wardrobe Diary（ワードローブダイアリー）** に直接保存します。

---

### 3.8 マーケットプレイス（再販、レンタル、交換、寄付）
ピアツーピア（P2P）の循環型ファッションマーケットプレイスに参加します。

- **出品の作成**: アイテムの詳細ページを開き、**Edit Intent（目的を編集）** を選択して非公開以外の目的を選択します：
  - *For Sale（販売）*: 出品価格と通貨を入力します（地域のロケール設定からデフォルト通貨を検出します）。
  - *Rent（レンタル）*: 1日あたりのレンタル料金と貸出条件を設定します。
  - *Swap（交換）*: アイテムをトレード可能としてマークします。
  - *Donate（寄付）*: アイテムを無償で公開します。
- **状態の同期**: 出品はフィードに自動的に反映されます。クライアントは `useSyncExternalStore` と IndexedDB キャッシュを使用して、遅延ゼロで検索パラメータを読み込みます。
- **試着サンドボックス**: 借り手／買い手は、チェックアウト前に自分のプライベートクローゼット内のアイテムと出品アイテムを組み合わせて試着テストを行うことができます。
- **取引チェックアウト**:
  - *購入／レンタル*: 統合された PayPal ボタンを介して取引を完了します。キャプチャされた Webhook が売り手に通知し、出品状態を販売済み／レンタル中に切り替え、7%のプラットフォーム手数料を差し引いた取引を台帳に記録します。
  - *物々交換（スワップ）*: 交換希望者がトレードを提案します。出品者には承認または辞退するための確認メールが届きます。

---

### 3.9 管理者パネルダッシュボード (Admin Panel)
システムの稼働検証、財務記帳、およびユーザーアカウント管理を行います。

1. `/admin` に移動します（管理者ロールのみ利用可能）。
2. **Overview（概要）**: 総取引量（Gross Volumes）とプラットフォーム手数料収入のサマリーを監査します。**Provider Activity Table** を検査して、下流の稼働統計（Gemini API、気象サービスのレイテンシ、およびエラー率）を表示します。
3. **Providers（プロバイダー）**: **Verify Key** をクリックして Gemini API に直接 ping を送信します。**Eyes Vision Override** スイッチを切り替えて、画像分析をデフォルトの Gemini エンドポイントとローカルコンテナの間でルーティングします。
4. **Users（ユーザー）**: アクティブなクレジット、ロール、および累計支払額を表示します。直接アクションを使用してユーザーを昇格または降格させます。
5. **Listings（出品）**: 出品の状態を表示し、アクティブフラグを切り替えて不正なアイテムを一時停止します。

## 4. 期待される結果

- **登録**: アイテムは即座（約16ms）にクローゼットグリッドに表示されます。背景の切り抜きはクリーンで透明な PNG 結果をレンダリングします。
- **DPP確認済みバッジ**: 有効なパスポートをスキャンすると、サステナビリティの詳細が記載された緑色の情報カードが表示されます。
- **アバターのアウター重ね着**: 2Dアバターキャンバス上で、帽子や靴が欠けることなく、トップスの上にアウターが正しく重なって表示されます。
- **音声応答**: バーチャルスタイリストのテキスト出力は、視覚的な波形インジケーターとともに自動的に音声オーディオを再生します。
- **サブスクリプション**: Manager または Professional プランにアップグレードすると、クローゼット容量上限の警告が即座に解除されます。

## 5. トラブルシューティング

### HTTP 402 Payment Required
- **問題**: 衣類の登録がブロックされました。クローゼットアイテムの基本上限である50点（または紹介ボーナス込みで最大150点）に達しています。
- **解決策**: **料金ページ**（`/pricing`）に移動して Manager または Professional プランを購読するか、招待リンクを共有して登録ごとに +10 スロット（最大150点まで）を獲得してください。

### DPP での SSRF ブロック / DNS エラー
- **問題**: スキャンしたQRパスポートのURLの解析に失敗します。
- **解決策**: パーサーは内部サーバーを保護するためにプライベートIPアドレス（`127.0.0.1`、`192.168.x.x` など）をブロックします。QRコードが公開ドメインを指していることを確認してください。

### カメラ／マイクの権限拒否
- **問題**: 撮影／スキャンビューポートに「X」エラー画面が表示されるか、音声入力が失敗します。
- **解決策**: ブラウザの権限設定を開き、ドメインに対するカメラとマイクのアクセスを有効にして再読み込みしてください。

### スタイリストチャットの失敗／レート制限
- **問題**: チャットにエラーが表示されるかフリーズします。
- **解決策**: サーバーは Gemini の `429` レート制限をキャッチし、ルールベースのクローゼット選択アルゴリズムにフォールバックします。インターネット接続を確認してください。

### メモリ不足 (OOM) による VPS スパイク
- **問題**: アップロード処理中に CPU/RAM がピークに達します。
- **解決策**: 登録処理は5点を超えるバッチに対して順次キューロックを利用します。サーバーに少なくとも 4 GB の RAM があることを確認してください。

## 6. 制限事項

- **ブラウザの Web Speech API**: ネイティブの Speech-to-Text 変換は Chrome と Safari に制限されており、他のブラウザは標準のテキスト入力にフォールバックします。
- **オフラインクライアント音声変調**: モバイルのオフライン Piper ONNX 音声合成は、サーバー側の Gemini オーディオモーダルよりも少ない音声プロファイルを使用します。
- **画像サイズの制約**: アバターおよびプロフィールのアップロード画像は、16MB の MongoDB ドキュメント境界内に収まるようブラウザ内でローカルに品質 82% に圧縮されます。
- **レシート解析の範囲**: 著しくぼやけた、歪んだ、または手書きのレシートは、データ抽出に失敗する場合があります。
