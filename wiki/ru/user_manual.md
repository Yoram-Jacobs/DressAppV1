# Полное техническое руководство пользователя DressApp

Исчерпывающее руководство пользователя и технический справочник по экосистеме личного гардероба DressApp, движку стайлинга, циркулярному маркетплейсу и панелям администрирования.

---

## 1. Обзор и технологический стек

DressApp — это персональный менеджер гардероба на базе ИИ, консультант по стилю и циркулярный маркетплейс. Платформа помогает пользователям управлять предметами одежды в цифровом виде, автоматически вырезать фон и размечать атрибуты, получать рекомендации нарядов с учётом погоды и календаря, сканировать цифровые паспорта изделий ЕС (DPP) и обмениваться одеждой или продавать её.

### Ключевое ценностное предложение
- **Оцифровка гардероба**: Обработка снимков с камеры или загруженных фотографий с автоматическим удалением фона, категоризацией одежды и генерацией тегов атрибутов.
- **Виртуальный ИИ-стилист**: Диалоговый агент, который анализирует контекст вашего гардероба, события Google Календаря и местный прогноз погоды для формирования ежедневных рекомендаций образов.
- **Циркулярный маркетплейс**: Безопасная одноранговая (P2P) покупка, продажа, обмен и аренда одежды для сокращения отходов быстрой моды.
- **Аналитика стоимости одной носки (CPW)**: Аналитические данные о капитализации гардероба, коэффициенте использования вещей и оптимизации их носки.

### Технологическая архитектура
- **Серверный контур (Backend Edge)**: Python 3.11 с фреймворком FastAPI и асинхронными драйверами Motor, подключёнными к выделенной локальной (on-premises) базе данных MongoDB 7.0 на накопителях NVMe.
- **Клиентское приложение (Frontend SPA)**: Одностраничное приложение на React 19, использующее кастомные хранилища на базе `useSyncExternalStore` (`stylistStore`, `dailySuggestionsStore`, `useOutfitStore`, `useClosetStore`, `useSuitcaseStore`), Tailwind CSS, примитивы Shadcn/UI и `react-i18next` с поддержкой 13 локалей.
- **Оптимизация состояния и сети**: Дедупликация выполняющихся запросов, 15-минутное кэширование хранилищ и ревалидация вкладок по событию `visibilitychange`, обеспечивающие полное отсутствие фоновых GET-запросов в режиме простоя.
- **Локальное машинное обучение и расчёт размеров**: Удаление фона на CPU с помощью локальной модели U2-Net (`rembg`), сегментация одежды SegFormer-b2, эмбеддинги Fashion-CLIP и регрессионная модель физических измерений тела ANSUR II (`body_predictor.py`). Включает выделенный локальный контейнер `dressapp-eyes`, в котором работает дообученная модель `Qwen 2.5 VL 3B` (`Qwen2.5-VL-3B-Instruct-Q4_K_M.gguf` + `mmproj`) на порту 7860 для обслуживания пользователей бесплатного тарифа (Free Tier) и автоматического резервного переключения при исчерпании квот.
- **Диалоговый синтез и распознавание речи (STT/TTS)**: Клиентское распознавание речи в реальном времени через Web Speech API в качестве резервного механизма, мультимодальные серверные голосовые модуляции Gemini и локальные офлайн-движки Piper/Sherpa-ONNX на устройстве.
- **Внешние интеграционные сервисы**: OpenWeatherMap API для получения данных о погоде, Google Calendar OAuth для синхронизации ежедневного расписания, автодополнение адресов OpenStreetMap (Nominatim) и REST API PayPal Subscriptions/Checkout.

## 2. Предварительные условия

### Требования к серверному окружению (хосту)
- **Оборудование**: VPS-сервер минимум с 8 ГБ ОЗУ (например, VPS Hetzner CPX32, на котором размещён рабочий контур `dressapp.co`).
- **Зависимости**: Стек Docker и Docker Compose (включая локальную базу данных MongoDB 7.0, бэкенд, сервер вывода ИИ eyes, фронтенд и терминацию TLS через Caddy).
- **Переменные окружения**: Конфигурация ключей API (`GEMINI_API_KEY`, `EYES_API_TOKEN`, `DEEPGRAM_API_KEY`, `OPENWEATHER_API_KEY`, `PAYPAL_LIVE_CLIENT_ID/SECRET` и токены Google Calendar OAuth).

### Требования к клиентскому приложению пользователя
- **Веб-браузер**: Google Chrome или Apple Safari (необходимы для полной совместимости голосовых функций).
- **Разрешения**: Предоставьте доступ к Камере (для съёмки одежды и сканирования QR-кодов) и Микрофону (для голосового общения).
- **Многоуровневый ИИ без собственных ключей (Zero-BYOK Tiered AI)**: Пользователи бесплатного тарифа используют локальную модель Eyes (`Qwen 2.5 VL 3B`) от DressApp; подписчики планов Manager и Professional пользуются быстрой облачной моделью (`Gemini 3.5 Flash`). Никаких пользовательских API-ключей не требуется.
- **Сеть**: Активное интернет-соединение для обработки запросов языковыми моделями (LLM); при этом кэширование в IndexedDB обеспечивает просмотр каталога гардероба в офлайн-режиме.

## 3. Пошаговые инструкции

### 3.1 Оцифровка одежды (Добавление вещей)
ПАРАДИГМЫ ДОБАВЛЕНИЯ: Фотосъёмка, цифровые паспорта изделий ЕС (DPP) и электронные коммерческие чеки.

#### A. Интерактивная камера, смешанная пакетная загрузка и автоматическая маршрутизация по 3 конвейерам
1. Перейдите на экран **Добавить вещь (Add Item)**.
2. Выберите **Сделать фото (Take Photo)** (запускает камеру устройства) или нажмите **Загрузить фото (Upload Photos)** (открывает системный диалог выбора файлов). Вы можете загружать несколько фотографий с разными характеристиками в одном пакете (отдельные вещи, полные образы на человеке/манекене и стопки/кластеры не надетой одежды) без ручного выбора вкладок режима.
3. Клиентское приложение вычисляет хеш SHA-256 и горизонтальный перцептивный хеш различий (dHash) каждого фото прямо в браузере (~100–180 мс) для сверки с вашим существующим гардеробом.
4. При обнаружении совпадения открывается **Диалог предварительной проверки дубликатов (Duplicate Preflight Dialog)** с превью похожих вещей. Выберите **Пропустить (Skip)** или **Всё равно добавить (Add anyway)**.
5. **Автоматическая маршрутизация по 3 конвейерам (`detect_photo_pipeline`)**: Для каждого принятого фото `clothing_parser.py` анализирует семантические маски SegFormer (`face_skin_ratio`, `anatomical_stack`, связные компоненты) и автоматически направляет фото в нужный конвейер:
   - **Конвейер `single`**: Отдельный предмет одежды со студийным альфа-маскированием (`rembg` + пересечение масок SegFormer).
   - **Конвейер `multi`**: Многосоставной образ на модели или манекене с выделением отдельных карточек верха, низа, верхней одежды, обуви и аксессуаров.
   - **Конвейер `mass`**: Группы не надетой одежды, раскладки flat-lay или несколько вещей на крючках (`parse_unworn_cluster`) с разделением несвязных компонентов и цветовой сегментацией watershed при сохранении нагрудных принтов.
6. Сервер передаёт прогрессивные кадры NDJSON (`detect`, `field`, `item`, `done`) за считанные секунды, позволяя сразу редактировать карточку, пока бэкенд завершает тегирование — включая точное различение **Толстовок и Худи (`Sweatshirts & Hoodies`)** от **Футболок (`T-Shirt`)** и распознавание более 60 **традиционных и культурных нарядов** на всех 13 языках.
7. Проверьте автоматически определённые теги (цвет, ткань, посадка, узор, дресс-код, повод). Если форма вырезки неверна, измените значение в списке **Категория (Category)** — это запустит автоматическую повторную обрезку предмета моделью SegFormer.
8. Нажмите **Сохранить (Save)** для мгновенной отрисовки предмета в сетке гардероба (~16 мс), пока в фоновом режиме завершается генерация миниатюр WebP и генеративное достраивание Nano Banana.

#### B. Сканирование цифровых паспортов изделий ЕС (DPP)
1. Нажмите кнопку **Сканировать QR (DPP)** на странице добавления вещи.
2. Предоставьте разрешение на использование камеры и наведите видоискатель на QR-код, напечатанный на фабричном ярлыке одежды, либо загрузите сохранённый скриншот QR-кода.
3. Бэкенд разрешает URL-адрес и выполняет проверки защиты от SSRF-атак (блокируя диапазоны частных IP-адресов).
4. Система извлекает разметку JSON-LD для получения сведений о бренде, составе материалов, цепочке поставок, углеродном следе и правилах ухода.
5. Проверьте извлечённые данные в зелёной раскрывающейся панели **Подтверждённые данные DPP (Verified DPP Data)** и нажмите **Сохранить (Save)**.

#### C. Импорт электронных коммерческих чеков
1. Откройте вкладку **Цифровой импорт (Digital Import)**.
2. Выберите подрежим: **Вставить текст (Paste Text)**, **Загрузить изображение (Upload Image)**, **Загрузить PDF (Upload PDF)** или введите **Веб-ссылку (Web Link)**.
3. Бэкенд использует мультимодальные визуальные модели для извлечения параметров покупки (бренд, цена, размер, категория).
4. Распознанные поля фиксируются на уровне чека для защиты от перезаписи при последующем визуальном анализе. Нажмите **Сохранить (Save)** для подтверждения.

### 3.2 Диалоговый виртуальный ИИ-стилист
Опишите свои затруднения с выбором одежды и получите голосовую консультацию по стилю в режиме hands-free.

1. Перейдите на экран **AI Stylist**.
2. Нажмите на значок микрофона `[Microphone]` в панели ввода чата.
3. Произнесите свой запрос (например: «Какой верх подойдёт к моим бежевым брюкам для обеда на открытой веранде в дождливую погоду?»).
4. Если браузер поддерживает Web Speech API, ваша речь транскрибируется в реальном времени прямо в поле ввода. В противном случае приложение записывает аудиофайл WebM и отправляет его на сервер.
5. Бэкенд направляет запросы пользователей бесплатного тарифа в локальный контейнер Eyes (дообученная модель `Qwen 2.5 VL 3B`), а запросы подписчиков планов Manager и Professional — в быструю облачную модель (`Google Gemini 3.5 Flash`) с автоматическим переключением на локальный движок Eyes при достижении облачных лимитов.
6. Стилист анализирует историю вашего гардероба, местный прогноз погоды и события календаря для формирования стилистического предложения.
7. Стилист озвучивает ответ с использованием выбранного голосового профиля (`puck`, `aoede` или `charon`).
8. Нажмите **Воспроизвести ответ (Play reply)** (или **Replay** в режиме иврита) на карточке, чтобы прослушать голосовое сообщение повторно.

### 3.3 Профиль, настройки и зависимости подсистем
Страница профиля служит главной панелью управления DressApp. Поля конфигурации напрямую влияют на производительность, маршрутизацию и поведение нижестоящих модулей.

##### Зависимости разделов аккордеона и их назначение

1. **Фотографии и сцена цифрового аватара (`AvatarViewer2D` и `DynamicAvatar`)**
   - **Почему это важно?**: Отображает ваш визуальный образ на всех холстах примерки с использованием двухрежимной сцены (сегментированная фото-вырезка реального тела либо динамический 2D-векторный SVG-манекен на кривых Безье).
   - **Зависимости подсистем**: Фото-вырезки очищаются от фона локальной моделью U2-Net (`rembg`) и масштабируются в браузере до максимума 1280 пикселей с качеством 82 %, чтобы гарантированно уложиться в лимит документа MongoDB (16 МБ). Сцена применяет откалиброванные позиционные привязки (`top-[14.5%]` совмещение воротника с линией шеи, `top-[36.5%]` совмещение пояса с линией талии, `bottom-[2%]` плоскость обуви) и пропорциональное масштабирование ширины груди/бёдер ($scaleX$). Нажмите *Удалить фото (Remove Photo)*, чтобы мгновенно переключиться обратно на 2D-векторный SVG-манекен.

2. **Профиль стиля (правила скромности, дресс-код)**
   - **Почему это важно?**: Устанавливает личные границы для рекомендуемых нарядов, предотвращая генерацию неприемлемых для пользователя стилевых предложений.
   - **Зависимости подсистем**: Выбранные параметры (например, ограничения скромности в одежде) передаются напрямую в системные промпты стайлинга для модели Gemini 2.5 Flash, отфильтровывая неподходящие элементы гардероба до их показа.

3. **Личные данные (имя, телефон, род занятий)**
   - **Почему это важно?**: Настраивает тон общения и маршрутизацию оповещений.
   - **Зависимости подсистем**: Имя пользователя динамически подставляется в электронные письма и системные push-уведомления. Номер телефона служит резервным идентификатором для запланированных оповещений. Параметр рода занятий передаётся языковой модели стилиста и алгоритму ранжирования персонализации Trend Scout для адаптации предложений.

4. **Измерения тела и подбор размеров (регрессионная модель ANSUR II и предиктор размеров)**
   - **Почему это важно?**: Избавляет от необходимости угадывать размеры, обеспечивая автоматический расчёт розничных размеров, сравнение с размерными таблицами внешних магазинов и точное виртуальное наложение слоёв одежды.
   - **Зависимости подсистем**: Ввод 4 базовых параметров (**Рост**, **Вес**, **Талия**, **Длина стопы**) запускает регрессионную модель scikit-learn ANSUR II (`body_predictor.py`), которая автоматически рассчитывает 6 структурных измерений (*Плечи*, *Грудь*, *Бёдра*, *Рукав*, *Внутренний шов*, *Внешний шов*).
     - **Детерминированный перевод размеров**: После прогнозирования непрерывных промеров серверный движок размеров динамически переводит их в розничные размеры одежды: **Размер рубашки** (XS–XXL по обхвату груди), **Размер брюк** (обхват талии в дюймах), **Размер обуви** (мужские/женские стандарты США и ЕС на основе длины стопы и пола), **Размер платья** (US 0–14+ по груди, талии и бёдрам) и **Размер бюстгальтера** (пояс + чашка на основе обхвата груди и расчётного обхвата под грудью).
     - **Автозаполнение**: Эти рекомендованные розничные размеры автоматически подставляются в поля *Режима детального редактирования (Detailed Edit Mode)* внутри панели профиля.
     - **Интеграции**: Измерения напрямую запрашиваются контент-скриптами расширения Chrome **Shopping Assistant** для чтения таблиц размеров на сайтах партнёров (Zara, Asos) и выдачи рекомендаций по размеру.

5. **Образ жизни (семейное положение, пол)**
   - **Почему это важно?**: Адаптирует базовые рекомендации и алгоритмы оценки контента.
   - **Зависимости подсистем**: Выбор пола напрямую влияет на логику ранжирования ежедневных карточек Trend Scout. Если гендерная категория новостной карточки не совпадает с полом пользователя, алгоритм начисляет штраф `-2.0` балла, понижая карточку в ленте.

6. **Маршрутизация моделей ИИ и тарифные планы подписки (многоуровневая архитектура Zero-BYOK и кредиты)**
   - **Почему это важно?**: Определяет маршрутизацию моделей по уровням подписки и расходование кредитов без необходимости ввода пользовательских API-ключей.
   - **Зависимости подсистем**: Пользователи бесплатного тарифа направляются в локальный контейнер Eyes (дообученная модель `Qwen 2.5 VL 3B`). Подписчики планов Manager и Professional направляются в быструю облачную модель (`Google Gemini 3.5 Flash`) с автоматическим резервным переключением на локальный движок Eyes при исчерпании квот.

7. **Планировщик и Push-уведомления (частота, ежедневный будильник, фокус стиля)**
   - **Почему это важно?**: Управляет автоматической ежедневной рассылкой предложений по стилю.
   - **Зависимости подсистем**: Активирует фоновые cron-задания `APScheduler` на бэкенде FastAPI. Каждое утро планировщик отправляет push-уведомления через `pywebpush` с использованием ключей VAPID клиента в соответствии с выбранными параметрами фокуса стиля.

8. **Google Календарь (синхронизация OAuth, правила экспорта)**
   - **Почему это важно?**: Напрямую связывает ваш гардероб с реальными событиями из вашего календаря.
   - **Зависимости подсистем**: Аутентификация выполняется через Google OAuth. Планировщик запрашивает ваш календарь для определения предстоящих мероприятий, формирует подходящие наряды и экспортирует запланированные образы прямо в расписание вашего Google Календаря.

9. **Службы геолокации (отслеживание GPS, точность погоды)**
   - **Почему это важно?**: Координирует рекомендации по погоде и фильтрацию локальных предложений по радиусу расстояния.
   - **Зависимости подсистем**: Запускает обратное геокодирование через `navigator.geolocation`. Координаты передаются в OpenWeatherMap API для корректировки рекомендаций стилиста (например, предложение непромокаемой одежды во время ливня). Также вычисляет расстояния для местных объявлений Маркетплейса и каталога экспертов (например, проверка радиуса в Лиссабоне).

10. **Голос и язык (выбор голоса виртуального стилиста)**
    - **Почему это важно?**: Устанавливает языковые словари интерфейса и голосовые модуляции.
    - **Зависимости подсистем**: Управляет активным языком переводов через `react-i18next`. Выбор голоса сопоставляет языковые коды BCP-47 (например, `he-IL` или `ar-JO`) с клиентскими голосами синтеза речи Web Speech или локальными офлайн-моделями Piper TTS.

11. **Приглашение друзей (API реферальных ссылок)**
    - **Почему это важно?**: Обеспечивает виральный цикл для бесплатного расширения вместимости гардероба.
    - **Зависимости подсистем**: Добавляет идентификатор MongoDB пригласившего пользователя к URL-адресу. При новых регистрациях система динамически проверяет этот ID и атомарно увеличивает поле `closet_capacity_bonus` пригласившего на +10 слотов, изменяя пороговые ограничители в модуле `closet.py`.

### 3.4 Панель аналитики гардероба (Wardrobe Insights)
Анализируйте капитализацию гардероба, отслеживайте частоту использования вещей и показатели стоимости одной носки (CPW).

1. Перейдите в раздел **Аналитика гардероба (Wardrobe Insights)**.
2. **Изучите ключевые метрики**:
   - *Стоимость гардероба (Closet Worth)*: Динамическая сумма цен покупки всех предметов.
   - *Использование гардероба (Closet Utilization)*: Процент вещей в гардеробе, надетых хотя бы один раз.
   - *Средняя стоимость одной носки (Average Cost-per-Wear, CPW)*: Вычисляется по формуле `Цена / Количество носок`.
3. **Графики распределения**: Переключайте вкладки для просмотра визуализаций Recharts:
   - *Цветовая палитра (Color Palette)*: Распределение сопоставленных HEX-кодов цветов.
   - *Материалы (Materials)*: Процентное распределение типов тканей.
   - *Подкатегории (Subcategories)*: Распределение предметов по подкатегориям.
4. **Таблица лидеров эффективности (Efficiency Leaderboard)**: Просматривайте топ-5 предметов одежды с самой низкой стоимостью одной носки (CPW).

### 3.5 Холст и планировщик образов (Outfit Canvas & Planner)

1. Откройте планировщик **Холст образов (Outfit Canvas)**.
2. **Многослойность верхней одежды (Двойной холст)**: Если ваш наряд включает верхнюю одежду (например, куртку) поверх топа, страница отображает два вертикальных модуля холста: «С верхней одеждой» (With Outerwear — показывает надетую сверху куртку) и «Без верхней одежды» (Without Outerwear — открывает вид на топ под ней).

4. **Вкладка оценки метрик (Metrics Tab)**: Нажмите кнопку подробностей и выберите вкладку **Метрики (Metrics)**, чтобы увидеть индикаторы совместимости по следующим критериям:

   - *Соответствие событию (Event Match)* (уместность для мероприятия)
   - *Соответствие локации (Location Match)* (проверка правил скромности)
5. **Переименование и описание**: Нажмите на значок карандаша, чтобы изменить название и описание образа.

### 3.8 Маркетплейс (перепродажа, аренда, обмен, дарение)
Участвуйте в одноранговом (P2P) маркетплейсе циркулярной моды.

- **Создание объявления**: Откройте страницу с подробным описанием вещи, выберите **Изменить статус (Edit Intent)** и укажите публичное назначение:
  - *Продажа (For Sale)*: Укажите цену и валюту (валюта по умолчанию определяется автоматически на основе региональных настроек локали).
  - *Аренда (Rent)*: Задайте суточный тариф аренды и условия проката.
  - *Обмен (Swap)*: Отметьте предмет как открытый для бартера.
  - *Дарение (Donate)*: Опубликуйте вещь для безвозмездной передачи.

- **Песочница примерки (Try-On Sandbox)**: Арендаторы и покупатели могут виртуально примерить вещь из объявления в сочетании с предметами из своего личного гардероба перед оформлением заказа.

  - *Покупка и аренда*: Завершите сделку с помощью встроенных кнопок PayPal. Обработанные вебхуки уведомляют продавца, переводят статус объявления в «продано/сдано в аренду» и фиксируют транзакцию в реестре за вычетом комиссии платформы в размере 7 %.
  - *Бартер (Обмен)*: Заинтересованные участники предлагают свои вещи для обмена. Автор объявления получает электронные письма с подтверждением, чтобы принять или отклонить предложение.

## 4. Ожидаемые результаты

- **Оцифровка вещей**: Предметы мгновенно отображаются в сетке гардероба (~16 мс). Вырезание фона создаёт чистые прозрачные изображения в формате PNG.
- **Значок верификации DPP**: Сканирование действительных цифровых паспортов открывает зелёную информационную карточку с данными об экологичности и происхождении изделия.
- **Верхняя одежда на аватаре**: Верхняя одежда корректно накладывается поверх топов на 2D-холсте аватара, не обрезая головные уборы и обувь.
- **Голосовой ответ**: Текстовые ответы виртуального стилиста автоматически воспроизводятся голосом с отображением визуального индикатора звуковой волны.
- **Подписки**: Переход на тарифный план Manager или Professional мгновенно снимает предупреждение об ограничении вместимости гардероба.

## 5. Устранение неполадок

### Ошибка HTTP 402 Payment Required
- **Проблема**: Добавление новых вещей заблокировано. Вы достигли базового лимита в 50 предметов гардероба (или до 150 предметов с учётом реферальных бонусов).
- **Решение**: Перейдите на **страницу тарифов** (`/pricing`) и оформите подписку на план Manager или Professional либо поделитесь своей реферальной ссылкой, чтобы получить +10 слотов за каждую регистрацию (максимум до 150 предметов).

### Блокировка SSRF / Ошибка DNS при сканировании DPP
- **Проблема**: Не удаётся обработать URL-адрес отсканированного QR-паспорта изделия.
- **Решение**: Парсер блокирует частные IP-адреса (например, `127.0.0.1`, `192.168.x.x`) для защиты внутренних серверов. Убедитесь, что QR-коды ведут на публичные домены.

### Отказ в доступе к камере или микрофону
- **Проблема**: В окне съёмки/сканирования отображается экран ошибки с символом «X» или не работает голосовой ввод.
- **Решение**: Откройте настройки разрешений браузера, включите доступ к Камере и Микрофону для домена приложения и перезагрузите страницу.

### Сбой чата стилиста / Ограничения частоты запросов (Rate Limits)
- **Проблема**: Чат выдаёт ошибки или зависает.
- **Решение**: Сервер автоматически перехватывает ошибки превышения лимитов `429` от Gemini и переключается на локальный движок или алгоритмический подбор из гардероба. Проверьте подключение к интернету.

### Скачки потребления памяти (OOM) на VPS
- **Проблема**: Пиковые нагрузки на CPU и ОЗУ во время загрузки фотографий.
- **Решение**: Система добавления вещей использует блокировки последовательной очереди для пакетов более 5 предметов. Убедитесь, что сервер оснащён достаточным объёмом оперативной памяти.

## 6. Ограничения

- **Браузерные Web Speech API**: Встроенное преобразование речи в текст (Speech-to-Text) поддерживается только в браузерах Chrome и Safari; остальные браузеры переключаются на стандартный текстовый ввод.
- **Офлайн-синтез речи на клиенте**: Мобильный офлайн-синтезатор речи Piper ONNX использует меньшее количество голосовых профилей по сравнению с серверной аудиомоделью Gemini.
- **Ограничения на размер изображений**: Загружаемые изображения аватара и профиля сжимаются локально в браузере до качества 82 %, чтобы гарантированно помещаться в 16-мегабайтный лимит документа MongoDB.
- **Точность распознавания чеков**: Сильно размытые, искажённые или написанные от руки квитанции могут не поддаваться автоматическому извлечению данных.
